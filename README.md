# سامانه مدیریت وظایف (Todo App) — فاز اول: اسپرینت اول

> **پروژه درس مهندسی نرم‌افزار**  
> **متدولوژی توسعه:** چابک (Scrum)  
> **معماری:** شی‌گرا (OOP) و لایه‌ای بر پایه اصول پنج‌گانه SOLID  

---

## ۱. معرفی پروژه
این پروژه نسخه اولیه یک سامانه مدیریت وظایف تحت وب است که در قالب **اسپرینت اول** از فاز اول درس مهندسی نرم‌افزار توسعه یافته است. تمرکز این اسپرینت بر توسعه قابلیت‌های پایه (**ثبت وظیفه**، **مشاهده وظایف**، **اعتبارسنجی دقیق ورودی** و **ماندگاری در پایگاه داده**) همراه با رعایت کامل **اصول طراحی شی‌گرا (OOP)**، **اصول پنج‌گانه SOLID** و استانداردهای کامنت‌گذاری **Color Block** بوده است.

---

## ۲. تکنولوژی‌ها و ابزارهای مورد استفاده (Tech Stack)
* **بک‌اند:** Python 3.10+ و FastAPI (سریع، امن و دارای مستندات خودکار OpenAPI/Swagger)
* **پایگاه داده:** SQLite + SQLAlchemy ORM (ماندگاری داده محلی و مستقل از سرور خارجی)
* **اعتبارسنجی داده:** Pydantic V2 (اعتبارسنجی دوطرفه ورودی‌ها و جلوگیری از مقادیر نامعتبر یا فاصله خالی)
* **فرانت‌اند:** HTML5 معنایی، CSS3 مدرن (پالت سرمه‌ای کهکشانی، فیروزه‌ای و کهربایی همراه با لبه‌های سه‌بعدی Specular و کلاس `:user-invalid` طبق استانداردهای Modern Web Guidance)، جاوااسکریپت ماژولار و رابط کاربری راست‌چین (RTL) با فونت Vazirmatn
* **تست خودکار:** Pytest و FastAPI TestClient (پوشش ۸ تست واحد و یکپارچگی)
* **کنترل نسخه:** Git

## ۳. معماری سیستم و رعایت اصول SOLID

پروژه به صورت لایه‌ای (Layered Clean Architecture) طراحی شده است:

```text
todo-list/
├── app/
│   ├── domain/                  # موجودیت‌ها و قراردادهای مستقل بیزینس
│   │   ├── entities.py          # موجودیت خالص TaskEntity
│   │   └── interfaces.py        # قراردادهای انتزاعی ITaskRepository و ITaskService
│   ├── infrastructure/          # ارتباط با پایگاه داده و ابزارهای خارجی
│   │   ├── database.py          # پیکربندی اتصال SQLite
│   │   ├── models.py            # مدل جدول وظایف در SQLAlchemy
│   │   └── sqlite_repository.py # پیاده‌سازی ملموس مخزن داده (Repository Pattern)
│   ├── services/
│   │   └── task_service.py      # لایه منطق بیزینس (Business Logic)
│   ├── schemas/
│   │   └── task_schema.py       # DTOها و قوانین اعتبارسنجی ورودی Pydantic
│   ├── api/
│   │   ├── dependencies.py      # تزریق وابستگی‌ها (Dependency Injection)
│   │   └── task_router.py       # اندپوینت‌های RESTful
│   ├── static/                  # رابط کاربری وب، استایل‌ها و اسکریپت‌ها
│   │   ├── index.html
│   │   ├── css/style.css
│   │   └── js/app.js
│   └── main.py                  # نقطه ورود اصلی برنامه FastAPI
├── docs/                        # مستندات کامل فرآیند اسکرام
├── tests/                       # مجموعه تست‌های خودکار واحد و یکپارچگی
│   └── test_tasks.py
├── run.py                       # اسکریپت هوشمند یافتن پورت آزاد و اجرای خودکار برنامه
├── start.bat                    # اسکریپت راه‌اندازی یک‌کلیکی مخصوص ویندوز
└── requirements.txt             # فهرست وابستگی‌های پایتون
```

### نحوه رعایت اصول پنج‌گانه SOLID:
1. **Single Responsibility Principle (SRP):** هر ماژول تنها یک مسئولیت دارد (مدل فقط ساختار جدول است، اسکیما فقط اعتبارسنجی، سرویس فقط منطق تجاری، و روتر فقط مدیریت درخواست‌های HTTP).
2. **Open/Closed Principle (OCP):** سیستم از طریق اینترفیس‌های انتزاعی (`ITaskRepository`) قابل توسعه است؛ برای مثال تغییر دیتابیس به PostgreSQL بدون تغییر کدهای لایه سرویس یا کنترلر امکان‌پذیر است.
3. **Liskov Substitution Principle (LSP):** پیاده‌سازی‌های مختلف از `ITaskRepository` (نظیر `SQLiteTaskRepository` یا `InMemoryTaskRepository` در تست‌ها) کاملاً بدون خطا جایگزین یکدیگر می‌شوند.
4. **Interface Segregation Principle (ISP):** اینترفیس‌ها متمرکز و بدون تحمیل متدهای اضافی تعریف شده‌اند.
5. **Dependency Inversion Principle (DIP):** لایه‌های بالا به لایه‌های پایین وابسته نیستند؛ هر دو به واسطه انتزاع (اینترفیس‌ها) به هم متصل شده و توسط FastAPI Dependency Injection تزریق می‌شوند.

## ۵. راهنمای نصب و راه‌اندازی سریع پروژه

### پیش‌نیاز:
* نصب بودن **Python 3.10** یا بالاتر روی سیستم

---

### روش اول: اجرای یک‌کلیکی در ویندوز (ساده‌ترین روش)
کافیست روی فایل **`start.bat`** در پوشه اصلی پروژه دبل‌کلیک کنید (یا در ترمینال عبارت `.\start.bat` را اجرا نمایید).  
این اسکریپت به صورت خودکار:
1. محیط مجازی (`.venv`) را در صورت نبودن می‌سازد و پکیج‌ها را نصب می‌کند.
2. یک پورت آزاد روی سیستم پیدا می‌کند تا تداخلی با پورت‌های رزرو ویندوز پیش نیاید.
3. سرور را اجرا کرده و مرورگر را به صورت خودکار باز می‌کند.

---

### روش دوم: اجرای دستی از طریق ترمینال (ویندوز، لینوکس، مک)

#### ۱. دریافت پروژه (در صورت کلون از گیت‌هاب):
```bash
git clone https://github.com/Esnoby/todo-list.git
cd todo-list
```

#### ۲. ساخت و فعال‌سازی محیط مجازی پایتون:
```powershell
# در ویندوز (PowerShell یا CMD)
python -m venv .venv
.\.venv\Scripts\activate

# در لینوکس یا مک
python3 -m venv .venv
source .venv/bin/activate
```

#### ۳. نصب وابستگی‌ها:
```bash
pip install -r requirements.txt
```

#### ۴. اجرای برنامه:
```bash
python run.py
```
*(اسکریپت `run.py` به صورت خودکار اولین پورت آزاد سیستم را پیدا کرده، لینک دقیق را در ترمینال نمایش می‌دهد و صفحه وب را در مرورگر شما باز می‌کند).*

همچنین در صورت تمایل به اجرای مستقیم با `uvicorn`:
```bash
uvicorn app.main:app --reload --host 127.0.0.1 --port 8100
```

* **آدرس مستندات تعاملی API (Swagger UI):** پس از اجرای سرور در مسیر `/docs` (مثلاً `http://127.0.0.1:8000/docs` یا `http://127.0.0.1:8100/docs`) در دسترس است.

## ۶. اجرای تست‌های خودکار (Automated Tests)
برای اجرای تمام ۸ تست واحد و یکپارچگی پروژه با Pytest:
```bash
pytest -v
```
*(یا در ویندوز بدون فعال‌سازی محیط مجازی: `.venv\Scripts\python -m pytest -v`)*
