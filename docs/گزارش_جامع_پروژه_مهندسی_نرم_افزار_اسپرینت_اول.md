# پروژه درس مهندسی نرم‌افزار — گزارش جامع فاز اول (اسپرینت اول)
### توسعه سامانه مدیریت وظایف (Todo App) با چارچوب اسکرام و اصول شی‌گرایی و SOLID

---

## شناسنامه پروژه و اعضای تیم
* **نام درس:** مهندسی نرم‌افزار
* **عنوان پروژه:** سامانه مدیریت وظایف تحت وب (Todo App)
* **دوره:** فاز اول — اسپرینت اول (توسعه قابلیت‌های پایه)
* **طول دوره اسپرینت:** ۲ هفته
* **اعضای تیم توسعه:**
  * **رضا:** مدیر محصول (Product Owner)، طراح و ناظر رابط کاربری (Frontend & Validation)
  * **آنتی:** معمار نرم‌افزار (Software Architect)، توسعه‌دهنده بک‌اند و پایگاه داده (Backend & Database)
* **استک فنی (Tech Stack):**
  * **Backend:** Python 3.11 + FastAPI
  * **Database:** SQLite + SQLAlchemy ORM (پایداری کامل داده‌ها در دیسک)
  * **Data Validation:** Pydantic V2 (اعتبارسنجی دوطرفه و جلوگیری از رشته‌های خالی و فواصل)
  * **Frontend:** HTML5 معنایی، CSS3 مدرن (پشتیبانی از `:user-invalid` و `:has()`)، جاوااسکریپت و استایل راست‌چین (RTL) با فونت Vazirmatn
  * **Automated Testing:** Pytest + TestClient (۸ تست واحد و یکپارچگی موفق)
  * **Version Control:** Git با رعایت اصول مهندسی در پیام‌های کامیت

### 🔹 جلسه ۱ (هفته اول — روز ۲): تصمیم‌گیری معماری و ساختار پروژه

### 🔹 جلسه ۲ (هفته اول — روز ۵): لایه داده، اعتبارسنجی و اندپوینت‌های API

## ۶. ساختار معماری و رعایت اصول پنج‌گانه SOLID
کد نرم‌افزار بر اساس معماری لایه‌ای تمیز در پوشه `app/` ساماندهی شده است:
1. **Single Responsibility Principle (SRP):** تفکیک کامل مسئولیت‌های Schemas (اعتبارسنجی ورودی)، Models (ساختار جدول دیتابیس)، Repository (ارتباط با دیتابیس)، Service (منطق بیزینس) و Router (پروتکل وب).
2. **Open/Closed Principle (OCP):** تعریف اینترفیس‌های انتزاعی تا سیستم برای افزودن قابلیت‌های جدید باز و در برابر دست‌کاری کدهای قبلی بسته باشد.
3. **Liskov Substitution Principle (LSP):** قابلیت جایگزینی کامل `InMemoryTaskRepository` با `SQLiteTaskRepository` بدون کوچک‌ترین تغییر در لایه سرویس (آزموده شده در تست‌های خودکار).
4. **Interface Segregation Principle (ISP):** اینترفیس‌های شفاف، کوچک و متمرکز.
5. **Dependency Inversion Principle (DIP):** تزریق وابستگی اینترفیس‌ها در FastAPI (`Depends`) به گونه‌ای که لایه‌های بالا به پیاده‌سازی مستقیم دیتابیس وابسته نیستند.
